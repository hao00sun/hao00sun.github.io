04 / 部署笔记 · 数据与纠正

π0.5 真机部署：数据要满足什么条件，什么时候用 DAgger？

部署失败后，先看策略遇到了什么状态、数据教过它什么，再决定补采什么。

旺仔 · 2026 年 11 月 17 日 · 数据方法 / 初稿
本文路线01 数据先要对齐重点：图像采集质量02 为何越做越偏03 DAgger 在补什么04 怎样记录接管重点：纠正数据筛选05 最小迭代闭环参考资料

部署时策略接收的是实时观测与任务指令；已有训练数据决定了它学过哪些状态和行为。这里讨论的是部署前的数据检查，以及部署失败后的纠正数据采集。

下文是面向 π0.5 的方法整理，不宣称已完成 DAgger 复现，也不把人工接管数据自动视为正确标签。

01 / 数据要满足哪些条件？

首先固定实现、checkpoint 和数据处理配置。LeRobot 与 openpi 的接口不能仅因为模型名相同就直接互换；具体字段和处理方式应对照所用版本的 LeRobot π0.5 文档或 openpi 文档。

条件重点检查
观测一致相机身份、视角、颜色与尺寸处理；状态字段、单位、关节顺序；指令与任务含义。
动作明确标签究竟是下发目标、增量还是测量位置；坐标系、夹爪含义、归一化与执行频率。
时序可靠图像、状态、指令与动作时戳对齐；记录丢帧、延迟、episode 边界与实际采样率。
覆盖部署对象、位置、光照、遮挡和初态范围；接近、接触、抓取与恢复阶段是否出现。
可独立验证按完整 episode 或采集批次划分训练与验证，避免相邻视频帧泄漏；另留固定真机评估场景。

对于动作块，还要核对未来动作序列与当前观测的对应关系。序列不能越过 reset 后接上另一个 episode；末尾不足长度时的 padding 和 mask 需遵循训练实现。数据文件能读取，只证明格式的一部分正确；LeRobotDataset 文档可用来核对存储与元数据。

没有适用于所有任务的固定示范条数。应先找覆盖缺口和标签问题，再决定增加哪些数据。同一初态下重复很多次，并不等于覆盖了偏离后的恢复动作。

图像质量，是我会优先检查的数据问题

对于依赖视觉判断物体与接触关系的 VLA，图像直接影响策略能从观测中获得什么信息。在我的采集检查中，图像质量会放在很高的优先级：动作做对了，但画面没有清楚记录任务关键信息，这条示范仍可能难以学习。这里强调它的重要性，不代表已经用对照实验证明图像在所有任务中都比动作标签、时序或任务覆盖更重要。

  • 背景与物体分辨不清：目标颜色、纹理与背景过于接近，或反光、阴影、曝光让边界消失，可能使目标位置、朝向和接触区域难以辨认。这类问题严重时，会明显削弱示范的有效信息。
  • 采集人大面积入镜：身体、手臂或衣物可能遮挡目标与机器人，也可能引入部署时不存在的视觉线索。若采集时总有人占据画面，而自主执行时人已离开，训练与部署的观测分布就发生了变化。

我的建议是：正式批量采集前，先录几条并按实际送入模型的裁剪、缩放结果回放，检查接近、接触、抓取与恢复阶段是否都看得清；调整相机视角、光照、背景和操作者站位，尽量避免无关人员遮挡任务区域。

清晰也要兼顾部署场景。不要只采一个理想背景就默认能适应所有现场；在关键任务信息可见的前提下，覆盖预期会出现的背景与光照变化。若任务本身就是人机交互，人的出现属于任务信息，应按实际使用方式采集。

02 / 为什么示范很顺，部署却越做越偏？

示意例子：专家每次都能准确到达杯口，所以示范大多集中在对准状态。策略部署时稍微偏到杯子右侧，接下来看到的画面和接触状态就不再像训练样本；后续动作继续出错，偏离可能逐步累积。

如果问题来自关节单位错误、相机接错或动作时序错位，应先修复数据和接口。继续采集纠正示范不能代替修复这些问题。只有在接口可信、主要缺口确实是状态覆盖时，讨论 DAgger 才更有意义。

03 / DAgger 聚合的是策略会遇到的状态

普通追加示范通常由专家重新完整执行任务。DAgger 的核心则是让当前策略参与产生访问状态，再由专家在这些状态上提供动作标签，将数据与已有数据聚合后重新训练。早期迭代也可以使用专家与学习策略的混合采样。参见 DAgger 原论文。

初始示范 → 训练策略
        → 策略访问状态 → 专家给出对应动作
        → 聚合旧数据与新标签 → 再训练 → 独立评估

这里的学习仍然可以是监督模仿学习，不需要因为发生了在线交互就称作强化学习。失败轨迹本身也不是专家标签：不能将策略失误动作原样放进 BC 目标，再期待策略学会纠正。

04 / 真机接管需要记录什么？

实际机器人上，人往往只在需要时接管。这属于人类干预式数据采集，接近 HG-DAgger 一类思路，但不等于自动复现了某篇论文的完整方法。HG-DAgger特别讨论了人类提供标签时的控制权和延迟问题。

除观测、指令与动作外，建议保留：控制权来源、接管开始与结束时戳、策略版本、策略建议动作、专家命令、实际执行命令，以及中止原因。这些是建议的追踪字段，不是声称某个框架已经自带的统一 schema。

接管时先确认旧的 action chunk 是否取消，什么时候控制权真正切换。人工反应与通信都有延迟，不能把后来发出的纠正动作无条件贴到更早的观测上。

混合纠正数据训练时，别把导致失败的动作也教回去

对于只有人工接管段具备专家标签的采集方式，我会先筛出接管后、控制权已经切换且质量合格的纠正数据，再与原始示范混合训练。接管前导致问题的策略动作，应从专家监督目标中去除或 mask；不能因为这个回合最后被人救回来了，就把整段轨迹都当成正确示范。

策略自主执行 → 逐渐偏离 → 人工切换控制 → 专家纠正 → 恢复
前段策略动作：不直接作为专家动作标签
切换过渡段：核对时戳与控制权，排除无效标签
专家纠正段：对齐观测与动作，审核后用于监督训练

示意例子：策略让夹爪逐渐偏离方块，随后人接管，将夹爪移回并完成抓取。应学习的是“处在偏离状态时，专家怎样纠正”，而不是把此前继续偏离的动作也当成专家行为。纠正开始时的偏离观测恰恰很重要，不能只保留最后已经回到正常轨迹的部分。

这里的“去除”指从专家监督样本或损失中排除错误动作，不删除原始录像、状态和日志。接管前的观测可在时间对齐且模型需要时作为历史输入；若专家另外对这些状态提供了可靠动作标签，也可以按 DAgger 的思路使用，不能把“只用接管后数据”当作所有 DAgger 方法的定义。

构造 action chunk 时，要检查监督窗口是否跨过控制权切换。按实际训练实现切段或逐步 mask，避免错误动作混入专家目标；切段后的 padding 不能伪造下一段轨迹。专家交还控制权后，策略重新执行的部分也不自动成为专家示范。

纠正采集应在硬件已校准、限位和急停有效的条件下进行，在风险状态之前干预。已经不可恢复或可能碰撞时，停止并重新布置，比为了补数据强行完成轨迹更合适。

05 / 一次小而完整的数据迭代

  1. 固定 baseline：用统一初态和指令评估当前模型，记录独立成功、接管、超时与失败阶段。
  2. 选一个覆盖缺口：例如接近目标后横向偏移。排除接口错误，再采集对应状态下的专家恢复行为。
  3. 审核与聚合：回放检查同步、控制权和标签；与旧示范一起训练，记录采样配比，避免只学恢复而丢掉原来的完整任务。
  4. 重新评估：使用相同协议比较，并检查原有场景是否退化。接管后的完成率和完全自主成功率分别报告。

希望得到的结论应当具体：哪类状态获得了覆盖，哪类失败减少了，付出了多少接管与标注成本。新数据数量本身不足以证明部署效果改善。
