01 / 工程实践 · 本体适配

把开源灵巧手策略迁移到另一种本体，需要检查什么？

先把策略到执行器的每一步说清楚，再判断该复用什么、重新训练什么。

旺仔 · 2026 年 11 月 17 日 · 方法整理 / 初稿
本文路线01 迁移的对象02 观测与动作03 本体与接触经验：Home 与初始难度04 对照与评估经验：迁移可能不如从零05 最小检查清单

换了一个灵巧手模型，网络还能输出动作，只能说明程序完成了部分连接。动作是否仍然表达原来的意思、任务是否仍然可达，需要分别验证。

本文整理通用检查方法，不包含特定公司的本体参数，也不宣称完成了所有检查或获得了迁移收益。

01 / 先说明“迁移”指什么

迁移可能指复用训练框架与任务设计，也可能指加载旧权重继续训练，或者直接在新本体上执行旧策略。这三件事的条件不同。复用算法代码，并不要求旧网络可以零样本控制新手。

开始前写一张差异表：源本体与目标本体的自由度、关节定义、观测字段、控制模式和任务目标。若输入输出维度不同，检查需要适配的网络层；若维度相同，也不能跳过语义核对。

例如，两只手各有相同数量的关节，但第一个动作维度在一只手上控制拇指外展，在另一只手上控制屈曲。张量形状完全正确，行为仍然可能完全错误。

02 / 沿着执行链检查观测与动作

观测与预处理→策略与动作映射→控制器与反馈
位置检查什么典型误判
观测关节顺序、单位、坐标系、历史窗口、缺失值和归一化统计字段同名，就认为含义相同
动作位置 / 增量 / 速度 / 力矩，动作尺度、零点与限位输出在 [-1,1]，就直接发送给 SDK
控制频率、保持方式、驱动增益、平滑、延迟与反馈时戳推理速度足够，就认为控制时序正确
权重网络结构、归一化器、历史状态、加载遗漏与初始化加载不报错，就认为所有权重都已生效

对于确实表示归一化绝对关节位置的动作，可以使用下面的映射。它不适用于未经解释的 PCA latent、力矩或位置增量：

q_target = q_min + (a + 1) / 2 × (q_max - q_min)
前提：a ∈ [-1, 1]，每维关节对应关系已确认。

在发送命令前做往返检查：归一化、反归一化后是否得到原来的目标位置？中位动作对应哪个姿态？正方向是否一致？同时记录策略原始输出与实际执行命令，观察限幅是否让大量不同动作变成同一个边界值。

03 / 几何与接触会改变原来的问题

URDF 中的关节轴、原点、限位以及连杆的碰撞和惯性描述，会影响模型表达的机器人。可视模型看起来正确，并不能替代碰撞与动力学检查。字段结构可参考 urdfdom 的 URDF 定义。

进一步需要看手指长度、拇指对掌范围、物体尺寸、质量、摩擦、初始位姿与接触关系。Home 姿态改变了探索的起点；原本容易形成的抓持包络，在另一只手上可能根本没有出现。

示意例子：奖励鼓励指尖靠近物体。更长的拇指可能通过向掌内折叠迅速降低距离，却没有形成稳定抓持。此时“奖励上升、物体仍掉落”是需要验证的现象，不能直接归因为 PPO 不稳定。

先把奖励分项、接触位置、手指轨迹和掉落事件对齐。若怀疑初始姿态，固定其他条件只改 Home；若怀疑奖励，再做相应对照。把本体、物体、Reward 和随机化一起改掉，通常很难解释结果。

训练极不理想时，先检查 Home 姿态

Home 是每次任务开始或 reset 时的初始手形。更换本体后，直接沿用旧手的关节角度，未必能得到相同的指尖位置与接触关系。它可能把原本可探索的任务，变成“一开始就掉落”“卡在掌心”或“很难建立有效接触”的任务。

强化学习对初始任务难度很敏感。尤其在接触复杂、成功反馈稀少的任务中，如果策略很少探索到接近成功的状态，就很难从交互中获得有用的学习信号。此时训练长期不理想，原因可能在初始状态，而不只在网络大小、学习率或训练时间。

我的掌内方块重定位经验：在观察不同手型和调整 Home 的过程中，我注意到：让方块由手指托起或夹持，使它远离并高于掌心，更容易形成可转动的初始状态。因此，换本体后训练表现很差时，我会优先检查方块与掌心、指尖之间的空间和接触关系，而不是立即继续加训练步数。

这是实践中的定性观察。指尖支撑可能给转动留出更多空间，也可能增加滑脱风险；现有记录还不足以把效果变化全部归因于 Home，不能据此认定“抬得越高越好”。

检查时先看 reset 后的静态姿态，再看最初一小段 rollout：方块是否穿透、是否立刻掉落、手指能否在不撞到掌心的情况下改变接触？之后在同一本体、物体、奖励、初始化和训练预算下，只改变 Home，比较目标达成、掉落与接触轨迹。

如果任务起点确实过难，可以先使用可稳定接触、目标旋转较小的初态，再逐步扩大初态和目标范围。最终仍要回到目标部署分布评估，避免只在精心摆好的 Home 上成功。

04 / 用同条件对照判断迁移价值

在同一目标本体、同一任务与评估协议下，比较“旧权重初始化”和“随机初始化”。保存权重加载记录，说明优化器和归一化统计是否继续使用。训练预算至少报告环境步数与实际耗时，不能只比较 epoch。

旧本体权重，也可能不如新本体从零训练

旧策略已经学到的手指协同、接触方式和动作偏好，未必适合新本体。尤其是拇指几何或对掌方式发生明显变化时，续训可能需要先纠正旧行为；从零训练则有机会直接探索适合新手的控制方式。这是迁移可能带来负面影响的一种解释，不是所有迁移任务的必然结果。

我的观察：在一次新旧手对比中，我遇到过新本体从零训练比加载旧手权重训练更快的情况，当时两只手的拇指差异较大。但训练速度的统一口径和完整对照条件还需要补齐，不能据此宣称从零训练的最终成功率一定更高。我也有迁移训练成功的记录，因此更实际的经验是：把从零训练保留为 baseline，让结果决定是否迁移。

评估同时报告成功数 / 总回合数、失败类型、掉落或越界、完成时间，以及初态与对象范围。通信异常或人工接管单独记录，不能静默删除后再报告漂亮的成功率。

仿真与真机分别统计。迁移早期学习更快、最终成功率更高、真机更稳是不同结论；一个视频不能同时证明三者。

05 / 我会按这个顺序推进

  1. 冻结基线：保存代码版本、资产、权重、最终配置与评估条件。
  2. 核对接口：逐维检查观测、动作及其预处理，确认没有把潜变量当关节量。
  3. 验证本体：检查 Home、初始穿透、接触与可达性，再开始训练对照。
  4. 逐级上机：在已校准的硬件上，经静止检查、受限单关节与低速动作验证，再进入任务；急停、限位与通信超时处理必须可用。
  5. 独立评估：固定协议，保留成功与失败证据，再决定迁移是否值得继续。

最终交付应当让另一个人知道：迁移了什么、改变了什么、如何运行、在哪些条件下有效，以及哪些边界仍未验证。
